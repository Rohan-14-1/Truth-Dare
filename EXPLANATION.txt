PROJECT OVERVIEW
================================================================================

Truth & Dare is a fully functional, browser-based party game built with vanilla 
HTML, CSS, and JavaScript. No backend or external libraries required (except 
Google Fonts). The game supports both single-player (local) and multiplayer 
(real-time Firebase) modes.

KEY FEATURES:
  • 2-10 players with unique color avatars
  • Animated spinning wheel for random player selection
  • 5 category packs: Friends, Couples, Office Party, Teens, Spicy
  • 3 difficulty levels: Easy, Medium, Wild (affects point scaling)
  • 225+ questions (15 truths and 15 dares per difficulty per pack)
  • No-repeat system (questions never repeat until pool exhausted)
  • Skip system (1 free skip per game with funny penalties)
  • 60-second dare countdown timer with animated progress ring
  • Real-time leaderboard with live score tracking
  • Game history log showing every question asked
  • Winner screen with confetti animation
  • Fully responsive design (desktop, tablet, mobile)
  • Multiplayer rooms with Firebase integration
  • Chat system for multiplayer games
  • Custom question support
  • AI question generation capability

3. assets/js/game.js — CENTRAL GAME STATE MACHINE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Purpose: Manages all game state and controls game flow. This is the "brain" 
         of the game.

Game States (State Machine):
  • LOBBY: Player setup phase
  • SPINNING: Wheel is spinning to select player
  • CHOOSING: Selected player chooses Truth or Dare
  • QUESTION: Question revealed, waiting for action (timer for dares)
  • VOTING: Other players voting thumbs up/down
  • RESULT: Showing score update
  • GAME_OVER: Final standings displayed

Key State Variables:
  • state: Current game state
  • currentPlayerIndex: Which player's turn it is
  • currentQuestion: The actual question text
  • currentType: 'truth' or 'dare'
  • currentRound: How many rounds have been played
  • totalRounds: How many rounds total (10 default)
  • turnsThisRound: Turn count within current round

Settings Object:
  • packs: Array of active question packs (e.g., ['friends', 'couples'])
  • difficulty: 'easy', 'medium', or 'wild'
  • totalRounds: Total rounds for the game (10 default)
  • aiEnabled: Whether AI question generation is active
  • aiVibe: Tone of AI questions ('chill', 'spicy', etc.)
  • customPackEnabled: Whether custom questions are enabled

Key Methods:
  • getState(): Returns current game state
  • getStates(): Returns all available states
  • setState(newState): Transitions to new state
  • advanceToNextPlayer(): Moves to next player in turn order
  • getSettings(): Returns current game settings
  • updateSettings(newSettings): Modifies game settings

  truthsData = {
    "friends": {

    "couples": { ... },
    "office": { ... },
    "teens": { ... },

No-Repeat System:
  • Tracks used questions in Set: usedTruths, usedDares
  • When pool exhausted (all questions used), resets tracking
  • Ensures same question isn't asked twice until cycle completes

  • activePacks: Which packs to draw from
  • activeDifficulty: Current difficulty level
  • customPackEnabled: Whether to include custom questions

Question Pools:
  • 5 packs × 3 difficulty levels × 15 questions = 225 total questions per type
  • Penalties list: Funny forfeit tasks for skipped turns

Key Methods:
  • loadData(): Fetches truths.json and dares.json from server
  • setActivePacks(packs): Sets which category packs to use
  • setActiveDifficulty(level): Sets difficulty (easy/medium/wild)
  • getNextTruth(): Returns next truth question (no repeat)
  • getNextDare(): Returns next dare question (no repeat)
  • getRandomPenalty(): Returns random skip penalty

Purpose: Calculates points, tracks voting, and maintains game history log.

Point System:
  • Easy: 1 point per correct/completed answer
  • Medium: 2 points per correct/completed answer
  • Wild: 3 points per correct/completed answer
  • Penalties: -1 point for skipping turn

Voting System:
  • Other players vote thumbs up (✓) or down (✗)
  • Majority vote determines if points awarded
  • Tied votes default to points awarded

History Log:
  • Tracks every question asked during game
  • Shows: Round #, Player Name, Question Type, Question Text, Score Change
  • Collapsible log UI for reference

Data Structure:
  history = [
    { round: 1, player: 'Alice', type: 'truth', question: '...', 
      scoreChange: +2 },
    ...
  ]

Key Methods:
  • recordQuestion(round, playerName, type, text): Adds to history
  • recordVote(playerId, vote): Tracks player vote (true/false)
  • calculatePoints(difficulty, votePassed): Returns points to award
  • getHistory(): Returns full history log
  • getHistoryForPlayer(playerName): Gets player's log entries
  • reset(): Clears history for new game

================================================================================
GAME FLOW (STEP-BY-STEP)
================================================================================

SINGLE-PLAYER FLOW:
━━━━━━━━━━━━━━━━━━━━

1. User opens index.html → app.js runs DOMContentLoaded event
2. Questions.loadData() loads truths.json and dares.json
3. UI.renderLobbyScreen() displays lobby with input field
4. User adds 2+ players → Players.addPlayer() adds each player
5. User opens Settings → configures packs, difficulty, rounds
6. User clicks "Start Game" → Game.setState('spinning')
7. Wheel spinner animates → Game.advanceToNextPlayer()
8. Current player sees Truth/Dare buttons
9. Player clicks Truth or Dare → Game.setState('choosing')
10. Card flips to reveal question from Questions.getNextTruth/Dare()
11. If Dare: Timer.start() (60-second countdown)
12. After completion: Game.setState('voting')
13. Other players vote thumbs up/down
14. Votes counted → Scoring.calculatePoints() determines score
15. Points awarded → Player score updates
16. Scoring.recordQuestion() adds to history log
17. Loop back to step 7 until totalRounds reached
18. Game.setState('game_over') → UI.renderWinnerScreen()
19. Confetti animation plays
20. User clicks "Play Again" to reset and start new game


MULTIPLAYER FLOW:
━━━━━━━━━━━━━━━━

1. User opens page → same as single-player
2. User clicks "Create Room" → Rooms.createRoom()
   • Generates room code (TRD-ABC)
   • Creates room in Firebase
   • User becomes host
3. Host shares room code with friends
4. Friends click "Join Room" → Rooms.joinRoom(roomCode)
   • Adds player to Firebase /rooms/{roomCode}/players
   • Shows waiting lobby
5. Firebase listeners trigger → MultiplayerUI updates in real-time
6. All players see each other joining
7. Host clicks "Start Game" when ready
8. Game.setState('spinning') syncs to all players via Rooms.broadcastGameState()
9. Each player sees same wheel spin
10. Turn flows same as single-player, but synced across all clients
11. Chat messages flow via Chat.sendMessage() → Firebase
12. All players see real-time score updates
13. Game ends → Winner screen shows on all clients simultaneously
14. Optional: Play again with same players

KEY ARCHITECTURE PATTERNS
================================================================================

REVEALING MODULE PATTERN (IIFE):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Each module (Game, Players, Questions, etc.) uses Immediately Invoked 
Function Expression (IIFE) to:
  • Encapsulate private data (closures)
  • Expose only public methods
  • Prevent global namespace pollution

Example:
  const Module = (() => {
    // Private variables
    let privateData = [];
    
    // Private functions
    function _privateHelper() { ... }
    
    // Public API
    return {
      publicMethod() { ... },
      anotherPublic() { ... }
    };
  })();

Benefits:
  • Data privacy (private variables can't be accessed externally)
  • Clear public interface
  • No global variable conflicts


STATE MACHINE PATTERN (Game.js):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Game uses explicit states with transitions:

  States: LOBBY → SPINNING → CHOOSING → QUESTION → VOTING → RESULT → GAME_OVER

Benefits:
  • Only valid state transitions allowed
  • Clear game flow
  • Prevents invalid game states


REACTIVE DATA PATTERNS (Firebase):
━━━━━━━━━━━━━━━━━━━━━━━

Uses Firebase listeners for real-time updates:
  • onValue() listeners watch database paths
  • Changes trigger callbacks
  • All clients stay synchronized automatically

Example:
  db.ref(`/rooms/${roomCode}`).on('value', (snapshot) => {
    const roomData = snapshot.val();
    // Update UI with new data
  });


NO-REPEAT ALGORITHM (Questions.js):
━━━━━━━━━━━━━━━━━

Prevents duplicate questions:
  1. Load question pool for selected pack/difficulty
  2. Track asked questions in Set (usedQuestions)
  3. When next question requested:
     • Get random index from pool
     • If in usedQuestions: try again
     • If not used: return question, add to usedQuestions
     • If all used: reset usedQuestions (new cycle)

================================================================================
TROUBLESHOOTING
================================================================================

Problem: "Failed to load question data" error
Solution: Ensure HTTP server is running (file:// protocol won't work)

Problem: Players not syncing in multiplayer
Solution: Check Firebase config in firebase-config.js is correct

Problem: Confetti not animating on winner screen
Solution: Ensure animations.css is loaded

Problem: Timer not showing for dares
Solution: Check timer.js module is loaded before game.js

Problem: Duplicate names not prevented
Solution: Check Players.addPlayer() validation logic

Problem: Questions repeating too often
Solution: Check Questions no-repeat Set is being tracked properly
